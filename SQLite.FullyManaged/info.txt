
The WITHOUT ROWID feature was introduced in SQLite version 3.8.2, 
which was released on December 6, 2013. 

Community.CsharpSqlite is a C# port of SQLite 3.6.1, which was released in August 2008. 
* The project was a line-by-line translation of SQLite's C source code into C#. 
* It was originally hosted on Google Code (before it shut down) 
  and later mirrored or forked into other repositories (e.g., GitHub). 

One archived description even says: 
 “Community.CsharpSqlite is a complete C# port of the SQLite 3.6.1 C code.”

What is a rowid in SQLite ? 
In SQLite, every table (by default) has a hidden rowid column that uniquely identifies each row. 
This acts like a built-in unique primary key, even if the table already has a declared primary key. 

* If id is defined as INTEGER PRIMARY KEY, then it aliases the hidden rowid, making them the same. 
* If no primary key is defined, SQLite still adds a hidden rowid. 


Adding WITHOUT ROWID to your table means: 
* No hidden rowid is created. 
* The table uses your declared composite primary key (zoom_level, tile_column, tile_row) 
  as the actual storage key. 
* It can improve performance and reduce storage if you're using a natural or composite primary key 
  (like in spatial or tile-based data).
